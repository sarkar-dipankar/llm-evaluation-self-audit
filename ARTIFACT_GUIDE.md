# Supplementary material

Anonymous artifact for *How Reproducible Are Evaluation Conclusions? A Self-Audit of LLM-Inferred Prompt Structure* (and its companion on prompt mutation visibility)

Everything needed to check the paper's numbers is here. Most of it runs **offline** from committed
raw outputs; the two exceptions are marked. There is no network dependency for any headline result.

```
tool/            Rust workspace implementing the analysis (crates + manifests)
tool/repairs.patch   the operator repairs, as a diff against the pre-repair state
scripts/         every analysis script named in the paper
results/         all measurements, including the raw per-run model outputs
corpus/          the prompts under test
requirements.txt Python dependencies (scipy is required for the statistical tests)
```

## Quick start

```sh
cd tool && cargo build --release && cd ..
export PATH="$PWD/tool/target/release:$PATH"
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Run any script from this directory, not from `scripts/`. Paths in the CSVs are relative to here.

## Reproducing the pre-repair state

The paper reports 1,644 mutants / 1,076 trace kills / 200 rendered-input kills before the operator
repairs, an 81% invisible share and a 5.38x oracle gap. Those are measurements, not reconstructions,
and this is how to check them:

```sh
cp -r tool tool-prerepair
cd tool-prerepair && patch -p1 -R < repairs.patch && cargo build --release && cd ..
python3 scripts/operator_visibility.py \
    --bin tool-prerepair/target/release/promptdbg \
    --out /tmp/prerepair.csv
diff /tmp/prerepair.csv results/pre_repair/operator_visibility.csv    # expect no differences
```

`repairs.patch` is the diff between the two states, scoped to the source files shipped here, so it
reverse-applies cleanly with no flags. Applying it in reverse to `tool/` yields the implementation as
it stood before the repairs described in §5; the five reverted files then match the pre-repair
commit byte for byte.

`results/pre_repair/` also holds `bench.csv` and its byte-identical copy
`bench_original_committed.csv` (both fully pre-repair, 1,644 mutants / 1,076 killed), and
`operator_visibility_intermediate.csv`, which is an **intermediate** state after the body-carrying
fix but before the same-guard restriction (1,246 / 797). That intermediate file is *not* the
"before" column and should not be diffed against it; it is included so the two cannot be confused.

## What is in `results/`

- `behaviour_raw/` — the raw model responses behind §6, five per condition per mutant. The
  statistics replay from these offline, so the section is checkable even though the model that
  produced them has since been withdrawn.
- `irs/`, `irs_crossed/` — persisted intermediate representations.
- `pre_repair/` — see above.
- everything else — the CSVs each script writes, committed so a reader can diff rather than trust.

## Corpus

- `corpus/synthetic/` — the 83 constructed annotated prompts (80 synthesised across 30 task domains,
  3 hand-authored). 60 render under the deterministic engine; the other 23 fail for several distinct
  reasons, documented in the paper.
- `corpus/contexts/` — generated input contexts.
- `corpus/github/` — 40 real-world `SKILL.md` prompts collected from public repositories under
  permissive licences (38 MIT, 1 Apache-2.0, 1 Unlicense), deduplicated by content hash.
  `corpus/MANIFEST.csv` records repository, path, commit, URL and licence for each.
- `corpus/github-annotated/` — 12 of those 40, hand-annotated. Deleting every inserted line
  reproduces each source file byte for byte; `ANNOTATION_NOTES.md` records every judgement call.

## Known limitations of this artifact

- The behavioural study cannot be re-collected: `gpt-oss:120b` was withdrawn by the provider after
  our measurements. The raw responses are included precisely because of this.
- `scripts/model_availability.py` and `scripts/failure_attribution.py` query a live endpoint and are
  not reproducible offline. Neither supports a headline claim in this paper.
- The per-operator split of the pre-repair 1,076 is reproducible via `repairs.patch` as above, but is
  not recoverable from the summary CSVs alone.
